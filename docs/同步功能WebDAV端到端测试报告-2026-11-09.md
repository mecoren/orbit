## 八、问题与建议

1. **WebDAV 大附件吞吐**：258 个附件 / 19.87 MiB 的全量上传 53 s、下载 75 s，其中 2 个 8.5 MiB 文件走分片通道。WsgiDAV 是单进程 Python 服务，生产环境（Nextcloud/群晖等）通常更快；建议保留「大附件分片」作为 WebDAV 基线，并在 `docs/17` 注明测试服务端实现，避免把服务端性能读成引擎性能。
2. **WebDAV 条件写语义**：本轮 `If-None-Match:*` 与 `If-Match` 不匹配均回 `412`，与 S3 方言分支（OSS 的 `x-oss-forbid-overwrite` + HEAD ETag 比对）行为一致；若接入对条件头不友好的 WebDAV 实现，需先看 `sync_history.error_message`。
3. **base_path 与服务端根目录共用**：本机 WsgiDAV 根目录同时容纳多轮测试前缀（`orbit-sync-test/...`），测试结束未做任何清理；建议测试机长期保留该目录并在 `dav_access.log` 里按前缀筛轮次。
4. **三端配置切换成本**：移动端清库后必须重填配置（`sync_configs` 在业务库内），且每次重启都要重新解锁同步密码；换协议（S3 ↔ WebDAV）要重填 endpoint/bucket/凭据与 base_path。属既定架构，建议在设置页提供「从备份/密钥包恢复配置」的一键入口。

1. **配置与连接为真机/桌面壳实测**：三端 WebDAV 配置重建、逐字段回显与「测试连接」均在真实壳上完成并通过（移动端 GUI 语义树取证，桌面 CDP 取证）。
