# 桌面开机自启动实现探索（2026-09-19）

> 范围：`apps/desktop`（Tauri 2 桌面壳）。移动端不涉及（无此概念，官方插件也明确不支持 Android/iOS）。
>
> **状态：已按方案 A 于 2026-09-19 落地**（改动清单见 §五、验证见 §七）。决策点按推荐值执行：
> 方案 A（官方插件）、自启一律隐藏启动、新建「通用」设置分类、不做启动期路径自愈
> （Tauri updater 走 NSIS 原地安装，exe 路径不变）。backlog 状态与实现要点见 `docs/07` #51。

## 一、结论先行

推荐 **`tauri-plugin-autostart`（Tauri 2 官方插件，v2.5.x）** + **`--hidden` 启动参数**：

- 插件本体是 `auto-launch` 0.5 的薄封装，跨三平台写系统级自启项，对外只有 `enable / disable / is_enabled` 三个动作；
- 自启时注册项带上 `--hidden`，进程照常起（托盘 + 四个后台守护齐全），但**不显示主窗**——正合「本地优先 + 关窗驻留托盘」的既有形态（`tray.rs` 关窗驻留、`window_recycler` 隐藏回收都是现成的）；
- 唯一新增业务面是**设置页一个开关**；Rust 侧只需一个 argv 解析命令让前端知道「这次是自启拉起的」。

有两处需要决策的地方（见 §六），其中 Windows 的「路径含空格」是唯一真正的坑。

## 二、官方插件的真实行为（已核对 upstream 源码，非文档口径）

插件 `lib.rs`（v2 分支）+ `auto-launch` 0.5 平台实现：

| 平台 | 落点 | 写入内容 | `is_enabled` 判定 |
| --- | --- | --- | --- |
| Windows | `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run`，值名 = app_name | `{exe_path} {args}`（**REG_SZ，路径与参数都不加引号**）；另写 `…\Explorer\StartupApproved\Run` 的 12 字节启用标记 | Run 值存在 **且** `StartupApproved` 末 8 字节全 0（即未被任务管理器禁用）→ 与系统「启动应用」开关联动 |
| macOS | `~/Library/LaunchAgents/{app_name}.plist`（`LaunchAgent` 为默认；`AppleScript` 模式走登录项，仅 `--hidden`/`--minimized` 有意义且需自动化权限） | `Label` + `ProgramArguments=[exe, ...args]` + `RunAtLoad=true`；**无 KeepAlive、不调 launchctl**（下次登录生效） | plist 文件是否存在 |
| Linux | `~/.config/autostart/{app_name}.desktop` | `Exec={app_path} {args}`（无引号转义）；**AppImage 场景用 `$APPIMAGE` 路径**（插件内部已处理） | .desktop 文件是否存在（**不读** `Hidden=true` / `X-GNOME-Autostart-enabled`） |

其他细节：

- app_name 默认取 `app.package_info().name`（= `tauri.conf.json` 的 `productName` → **`Orbit`**），可用 `Builder::app_name()` 覆盖；
- args 由 `Builder::args(["--hidden"])` 在构建期注入，写进各平台注册项的命令行 / plist `ProgramArguments`；
- macOS LaunchAgent 模式下 `app_path` = `current_exe()` 的 canonicalize 结果（只有 AppleScript 模式才截到 `.app` 根）；
- Rust 版本要求 ≥ 1.77.2（仓库锁 1.96 ✅）；crate 内部 `#[cfg(not(any(android, ios)))]`。

### 已知坑（必须写进实现说明或规避）

1. **Windows 路径含空格 → 自启静默失败**：`auto-launch` 拼命令行不加引号，`C:\Program Files\Orbit\orbit.exe --hidden` 会被 CreateProcess 解析成 `C:\Program`。MSI 默认装 `C:\Program Files\`、或用户名含空格（`C:\Users\John Doe\AppData\Local\Orbit`）时踩中。
2. **Linux `is_enabled` 只看文件存在**：用户在 GNOME「启动应用程序」里禁用后可能仍显示为开启（重开一次开关会覆盖写回）。
3. **卸载不清自启项**：NSIS/MSI 卸载不删 Run 值 / plist / .desktop（插件无卸载钩子），残留项在登录时静默失败——建议文档提示「卸载前先关闭开关」。
4. **dev 模式注册的是 `target/debug` 路径**：功能验证必须用打包产物；平时 dev 打开了记得关。
5. **加密库的先天限制**：主密码解锁前 DB 未就绪，提醒轮询守护不工作——自启在「加密模式」下只等于「提前就绪」，真正免打扰的离线提醒仍靠 Windows 计划 Toast（已有，`scheduled_toast.rs`）；明文库模式自启即全功能。建议在设置页说明文案里点一句。

## 三、与现有架构的咬合点（仓库现状核对结论）

- 窗口配 `visible: false`，由前端 `apps/desktop/src/main.tsx` 初始化主题后 `getCurrentWindow().show()`——**「自启不显示主窗」必须在这里分叉**，否则会闪窗（`window_recycler::create_main_window` 也依赖同一条 show 链）。
- `window_recycler::schedule_recycle_on_hide`（隐藏 5 分钟销毁主窗、进程与守护常驻 ~40MB）与 `webview_low_power::set_memory_usage_level` 正是自启隐藏后想要的路径——**隐藏启动时顺手接上，自启常驻内存从 ~330MB 落到 ~40MB**（与 `docs/adr/0006` 口径一致）。
- 托盘（`tray.rs`）、全局热键、快速新建意图补发都按「窗口可能不在」写好了，隐藏/销毁态唤起无缺口。
- 设置页 = `pages/settings-page.tsx` + `components/settings/categories.ts` 分类模型 + 每分类一个 `*-section.tsx`（`todo-section.tsx` 的 Switch 卡片是最接近的样板）。
- IPC 约定：命令在 `src-tauri/src/lib.rs` 的 `invoke_handler` 集中注册、前端包在 `src/lib/tauri.ts`、浏览器 mock 同步 `src/test/ipc-mock.ts`。
- 现成可复用的依赖：`apps/desktop/src-tauri/Cargo.toml` 已声明 `windows-registry 0.6`（写 HKCU）——若走自研 Windows 实现无需新增依赖。

## 四、方案对比

### 方案 A：官方插件（推荐起步）

- Rust：`Cargo.toml` 桌面 target 段加 `tauri-plugin-autostart = "2"`；`lib.rs` 里 `#[cfg(desktop)] .plugin(tauri_plugin_autostart::Builder::new().args(["--hidden"]).build())`。
- 权限：`capabilities/default.json` 加 `autostart:allow-enable` / `allow-disable` / `allow-is-enabled`。
- 前端：`pnpm add @tauri-apps/plugin-autostart`，设置分区里动态 `import()`（照抄 `updater-section.tsx` 的写法，mock 环境失败收敛到 toast）。
- 另加一个 Rust 命令 `startup_launched_hidden()` 供 `main.tsx` 判断是否 show。
- 成本：约半小时接线 + 1 个设置分区；风险集中在 §二 的坑 1。

### 方案 B：仓库自研三平台薄实现（仅在不能接受坑 1 时）

- 新增 `commands/autostart_cmd.rs`，三平台各自 ~30–40 行：
  - Windows：`windows-registry`（已是依赖）写 `"C:\…\orbit.exe" --hidden`（**正确加引号**）+ 读回时顺带校验路径（可检测更新/移动后的路径漂移并自愈）；
  - macOS：写 `~/Library/LaunchAgents/cn.wait.orbit.plist`（Label/ProgramArguments/RunAtLoad）；
  - Linux：写 `~/.config/autostart/orbit.desktop`（按 Desktop Entry 规范加引号、AppImage 取 `$APPIMAGE`，并正确处理 `Hidden=`）。
- 不引插件、不加 npm 依赖、不加 capability；命令面与方案 A 完全一致（`autostart_is_enabled` / `autostart_set_enabled`），将来 A→B 切换前端零改动。
- 成本：+120 行左右 Rust（含单测）+ 三平台手测；换来引号正确性与路径自愈。

> 建议：**先按 A 落地**；把坑 1 记为已知问题，等实机（MSI 装 `Program Files` 的用户）反馈再评估切 B，接口不变。

## 六、待决策点

1. **方案 A / B**：是否接受 Windows 路径含空格时自启失效（A 的代价）？
2. **自启是否一律隐藏启动**：推荐「是」（不闪窗、贴合托盘驻留），暂不做「显示主窗」的二档开关。
3. **设置入口**：新建「通用」分类（推荐，未来收纳启动项/数据目录等）vs 并入现有「关于与更新」。
4. **路径自愈**：是否在每次启动时「若已启用则 re-enable 一遍」以刷新注册路径（方案 A 下 `enable()` 幂等，可覆盖升级/移动后的漂移；代价是启动写一次注册表）。方案 B 天然能做（读回校验）。

## 七、验证清单

**Rust 单测**：`launched_hidden` 纯函数（含 `--hidden` 精确匹配、无参、混合参数、`--hidden=1` 不应误判）。

**实机（必须打包产物，dev 路径无意义）**：

- Windows：开启 → `reg query HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run` 见 `Orbit` 值；注销重登 → 托盘出现、无窗口、任务管理器内存为宿主档；任务管理器「启动」页禁用 → 设置页显示关闭；路径含空格的安装场景单独验一次（预期踩坑 1）。
- macOS：`~/Library/LaunchAgents/Orbit.plist` 生成、重登后无 Dock 窗口（LaunchAgent 模式需自行隐藏，靠 `--hidden`）。
- Linux：`~/.config/autostart/Orbit.desktop` 生成、AppImage 场景 `Exec` 指向 `$APPIMAGE` 而非 `/tmp/.mount_*`。

**回归**：托盘唤起 / 热键 Alt+Shift+O / 隐藏 5 分钟回收后重建 / 双击 exe 正常显示主窗（无 `--hidden`）。
