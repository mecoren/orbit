# ADR 0013：本地启发式日排程（Day Planner）

日期：2026-10-24 ｜ 状态：已采纳（阶段一落地）｜ 来源：docs/13 §五 F3（docs/07 #100）

## 背景

`duration_minutes`（#67/#72）与容量条（#82/#86）回答了「今天排了多少」，但不回答
「先做哪个、放在几点」。云端 AI 排程（Motion / Reclaim / Sunsama）与本项目
零遥测、无账号的定位冲突；docs/13 论证了「本地规则 + 可解释 + 可撤销」的轻量
排程不冲突，且地基（时长、容量、我的的一天、工作窗语义）已齐。

## 决策

1. **算法为 core 纯函数**（`day_planner_api::plan_day_slots`），完全在
   「相对今天零点的分钟」整数域运算——零 chrono 依赖，DST 安全；毫秒 ↔ 分钟
   换算只在 `plan_day` API 边界做一次。相同输入相同输出（排序全键稳定：
   bucket → 桶内 key → duration → id），支撑「为什么排在这」的解释与单测。
2. **排序五桶**（docs/13 F3 口径）：逾期（due 升序，最老先）→ 今日带时刻截止
   （EDF，截止时刻升序）→ 纯日期截止（优先级降序）→ 我的一天 → 未排期带时长
   （两者优先级降序）；桶内 duration 升序（短任务优先填空档）→ id 升序兜底稳定。
3. **硬约束**：不排到过去（now 向上对齐粒度）；工作窗（默认 09:00–18:00）挖
   午休（12:00–13:00）成两段；今日带时刻的截止是硬线——放不下即未排入
   （reason「晚于截止 HH:mm」），**不挪截止、不压缩任务**；固定时长放不下则
   顺延下一段/未排入。无时长任务按偏好兜底（默认 30 分钟）。
4. **阶段一 = 只读预览**：`day_plan_preview` 不写库、不 emit、不进同步白名单
   （与统计同族的只读聚合）；双端 UI 均显式标注「只读预览」。**阶段二 = 应用
   写入**：写 `my_day_date` + `start_date`、**不改 `due_date`**，单事务批量 +
   保存快照撤销——另行立项后实施。阶段三 = 偏好编辑（cfg_kv 本地，不参与同步）。
5. **超载只提示不阻断**：`load_minutes > capacity_minutes` 时前端给警示条与
   超出分钟数；未排入清单带原因，不放任静默丢弃。
6. **候选口径**：今日到期 / 逾期（`include_overdue` 开关）/ 我的一天（今天）/
   未排期且带时长，均须未完成未软删；`fetch_all` 由日期窗口与谓词天然收敛，
   上界登记 docs/14 C 档。

## 后果

- 正向：零新依赖、零 DDL、零协议；双端各约半天 UI 接线；理由徽标让用户能
  校验排序是否符合直觉；确定性使 golden 用例可锁定（11 例纯函数 + 3 例 API）。
- 负向（有意取舍）：偏好阶段一写死默认值（双端 `DAY_PLAN_DEFAULT_PREFS`），
  用户改不了作息——阶段三补；不处理日历事件/手动时间块占用（现有 start_date
  语义是「开始时间」而非「已占用块」，阶段二应用时再定义互斥语义）。
- 与 G8（云端 AI）的边界维持：本能力全部本地计算，不联网。
