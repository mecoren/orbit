## 八、问题与建议

1. **底栏「更多」按钮 hit test 失效（产品缺陷，建议修）**：干净重启后 `input tap` 对顶栏、列表、FAB、以及底栏「视图/清单/日历/四象限」均生效，唯独 `[928,2432][1147,2576]` 的「更多」整段无响应；`input keyevent` 有效，`sendevent` 写 `/dev/input/event4` 亦无效；键盘 TAB/DPAD 焦点遍历 45 次也从未进入底栏「更多」。本轮绕道「清单 → 页头设置」完成取证，但该按钮对用户而言是设置/回收站等模块的唯一入口，建议排查 `HomeShell` 底栏的 `HitTestBehavior` / 玻璃 Overlay 拦截。证据 `gui/tab-*.txt`、`gui/probe-*.xml`、`probe_bottom.py`。
2. **测试连接轻提示易漏抓**：结果以短时轻提示呈现（约 1 s），自动化需在 0.5 s 内取语义树。本轮移动1 抓到「连接成功（根目录 1 个条目）」。
3. **误触防护**：脚本曾因包含匹配回退弹出「清除本机同步密码缓存？」确认框（已取消，未执行）。已把按钮匹配收紧为精确匹配，并在脚本中显式列出禁止点击的高危按钮。建议 UI 自动化统一禁用模糊匹配。
4. **验收字段与实现不一致**：需求要求记录 `sync_state.downloaded_chunks`，`SyncState` 无该字段。建议补计数或修订验收文档为 `pulled_modules` / `downloaded_attachments` + 桶指纹；本轮用后者 + 桌面 D2 前后账本比对替代。
5. **WebDAV 吞吐**：258 附件 / 19.87 MiB 全量上传 42,462 ms、下载 55,398 ms（核心测试台）；真机移动2 全量 pull 78,285 ms、移动1 105,906 ms；真桌面壳 97,451 ms。WsgiDAV 是本地单进程 Python 服务，服务端性能不应读成引擎基线，建议单独建档。
6. **S3 独立对象列举 403 已修复**：根因是列举工具保留 query 中的 `/` 且优先 path-style；生产适配器对 `aliyuncs.com` 用虚拟主机风格，且 `build_canonical_query` 用 `urlencoding::encode` 把 `/` 编码成 `%2F`。按生产口径修正后，S3 的 `/s3`、`/s3-clean`、`/s3-devices` 各列举出 784 个对象（S3 报告第五节）。建议云端对象审计统一走生产适配器口径。
7. **附件「可打开」已升级为应用内实证**：本版补做桌面 IPC `task_attachment_export` 流式导出两个 8.5 MiB 附件（各 8,912,896 B、sha256 与内容寻址名一致、已向系统发出打开请求），以及移动1 GUI「打开附件」生成缓存文件（8,912,896 B、`sha256sum` 一致）。详见 S3 报告第七节。随机二进制附件无关联预览器，故「打开」以应用自身读取/导出链路为准。
8. **文档口径**：run4 报告「合计 215,409 行」为算术错误；建议报告合计由脚本求和生成。报告文件名按需求沿用 `2026-11-09`，实际执行 2026-11-11。
