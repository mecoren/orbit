## 五、指标体系与对标（量化实测）

> 测量环境：AMD Ryzen 7 7840H（8C/16T）/ 28GB RAM / Win11；测量工具入库 `perf-metrics/`（cold-start.mjs 冷启动、interaction.mjs 万级交互、memory3.mjs 进程组差分内存/CPU），全部可复现。
> 版本快照法：pre = `5c17def`（批次2/3 前的完整前端构建），post = `df66dd3`（全优化后）；Rust release exe 同一构建（批次4 后）。同一 Chrome 通道加载两版 dist，同一种子数据，逐指标对比。

### 5.1 指标定义与口径

| 指标 | 定义 | 采集口径 |
|------|------|----------|
| 冷启动时间 | 进程 spawn → 主窗显示 → +400ms 交互缓冲 | MainWindowHandle 轮询（20ms 步进），5 轮/组 × 3 组取中位 |
| 勾选完成端到端 | click → mock db.done 落 1（写链+失效+重拉） | 万级任务首行，15 轮取中位/p95；DB→DOM 同帧差经单次探针验证 ≈1ms |
| 滚动流畅度 | 10 屏连续滚动的 rAF 帧间隔分布 | 中位帧间隔 + p95 帧间隔（<17ms≈60fps） |
| 看板切换首渲染 | 点切看板钮 → ≥10 卡片可见 | performance.now 差 |
| 内存占用 | 进程组 WorkingSet 差分（启动前系统基线净增） | orbit-desktop+msedgewebview2 全树 / Chromium 全树，稳定期 + 操作期 |
| CPU | 进程组累计 CPU 秒（Get-Process CPU 合计） | 固定窗增量：启动 10s 窗 / 操作期（10 屏滚动+5 勾选） |

### 5.3 测量边界（哪些收益在此环境测不出）

- **db-change 表级失效（F1）的收益主体在真机 Tauri IPC**：mock IPC 是进程内同步函数，「勾选一条任务从 9+ 路查询重拉收敛到 5 路」中的 IPC 往返与桥序列化开销在 Chrome mock 下不存在，故勾选延迟 pre/post 均落在 ~250ms 噪声带。真机下该优化的量级推算：每次写操作省 4 路无效查询（含三路万行级全量列表的 JSON 序列化/反序列化往返），参考既有实测（2026-09-10）万行单列表过桥 ~50-80ms，估算单次勾选省 150-250ms——待真机验收项。
- **TaskRow memo（F3）收益在交互期**：本测量滚动 60fps 两版均已达标（虚拟化早已落地），memo 消除的是拖拽/多选态 set 时的整窗重渲——体现为高频交互下的 CPU 尾延迟，本测量窗未单独隔离该项。
- 冷启动首轮（3.3s）为冷磁盘缓存离群值，已剔除。

### 5.4 对标（沿用 2026-09-10/11 实测口径）

| 对比项 | Orbit（本批后） | 参照 | 说明 |
