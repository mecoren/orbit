# 01 产品需求 —— MVP 范围

## 一、产品目标

把 wait-home 中打磨成熟度最高的待办模块独立为单一职责产品：一个**桌面优先、本地优先、端到端加密**的待办应用。MVP 的定义是：**在桌面三端达到"可日常自用、数据可靠、同步可用"，移动双端达到"基础链路可用且观感复刻到位"。**

成功判据（按优先级）：
1. 桌面端功能与 wait-home 现版对齐（复刻验收清单全过）
2. 两台设备间 E2E 加密同步收敛正确（LWW 无僵尸行）
3. 五端安装包均可产出；移动端完成核心四屏复刻

## 二、非目标（MVP 明确不做）

| 不做 | 理由 |
|---|---|
| 重复任务引擎 | wait-home 中仅有字段占位，无引擎。字段保留但 UI 隐藏 |
| 自然语言快速输入 | 超出复刻范围 |
| 协作 / 指派 / 共享 / 订阅 | 单用户产品定位 |
| 日历视图 / 已保存筛选器 | 复刻范围外 |
| 第三方导入迁移工具（Todoist 等） | M6+ 再议 |
| Widget / 徽章 / 托盘快捷操作 | 后续版本 |
| 多语言 / i18n | 全部界面文案定死中文，不做翻译层 |
| Web 版 | Tauri 不覆盖；React 代码保留将来抽 SPA 的可能即可 |

### 3.5 移动端专属范围（05 文档为准）

MVP 移动端四屏链路：`侧栏首屏 → 任务子列表 → 详情全屏` + `新建/编辑底部抽屉表单`。
明确排除：看板、todo_list_page 未接线版的搜索展开/视图切换器（记入 M6+）、侧滑手势操作（长按菜单替代）。

## 四、平台验收矩阵

| 平台 | 打包目标 | MVP 验收级别 |
|---|---|---|
| Windows 10/11 x64 | NSIS + MSI | **A 级**：全部功能 + Mica + 开机常驻提醒轮询 |
| macOS 12+ (Apple Silicon) | DMG | A 级（Mica 替换为 vibrancy，其余同） |
| Linux x64 (Ubuntu 22.04 基准) | deb + AppImage | B 级：功能全过，窗口材质允许降级为纯色 |
| Android 10+ | APK | C 级：四屏链路 + 本地通知 + 同步开关可用；性能不作硬性指标 |
| iOS 15+ | IPA（TestFlight） | C 级：同 Android；签名证书就绪为前置条件 |

## 五、MVP 验收标准（DoD）

### 桌面
- [ ] 复刻验收清单（04 文档 §8）逐项通过，截图对照 wait-home 无观感级差异
- [ ] 新建→编辑→子任务推进→标签→提醒→完成 全链路无阻塞性 bug
- [ ] 看板拖拽：跨列移动改 project/status，列内排序 position 取中值，刷新后顺序稳定
- [ ] 主密码设置/解锁/修改流程完整；错误密码连续失败不损坏库文件
- [ ] 双设备（实机 + 第二目录实例）WebDAV 同步：新增/编辑/删除三类变更双向收敛，断网重连后补推成功
- [ ] 提醒触发率 100%（20s 轮询窗口内），超期 24h 以上陈旧提醒不补弹

### 移动
- [ ] 四屏观感对照 Flutter 版逐屏通过（玻璃三件套：blur+tint+1px 高光线）
- [ ] 列表滚动 60fps（500 条任务基准）
- [ ] 通知权限拒绝时降级为应用内 toast，不崩溃

### 工程
- [ ] CI 产出五端构建产物（iOS 允许手动触发）
- [ ] 迁移链从空库到最新版可重复执行（含 SQLCipher 密钥注入路径）
