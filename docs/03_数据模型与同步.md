### todo_tasks 关键列
```
position        REAL      -- 看板/列表排序键；拖拽取中值算法：((prev?.position ?? 0) + (next?.position ?? 100000)) / 2
```

## 四、数据库打开流程（Tauri 壳）

```
前端启动 → master_auth_has()
 ├─ false → db_init_plaintext(app)            # 免密模式：明文库直接 init_pool_unencrypted
 └─ true  → 解锁页 → master_auth_unlock(pw)
              → derived_key = PBKDF2-HMAC-SHA256(pw, salt, 600_000)
              → 解密 master_auth.json 中 encrypted_db_key → 32B DB Key → hex 化(64 字符)
              → db_init_encrypted(db_key_hex):
                  SqliteConnectOptions(WAL · busy_timeout 5s · max_conn 10)
                  PRAGMA key = x'<hex>'       # SQLCipher 解锁
                  PRAGMA foreign_keys = ON
                  sqlx::migrate!("./migrations").run(&pool)
              → manage(AppState{pool}) → 启动 EVENT_BUS → emit("db-change") 转发任务
```
master_auth.json 格式 v2：`verify_hash = SHA-256(derived_key)`（v1 存 raw derived_key，首次解锁自动升级）。文件族命名见 02 文档 §八（`orbit.db` 等）。

## 五、提醒轮询守护（notification_scheduler）

桌面端 tauri-plugin-notification 不支持定时触发，故采用常驻轮询：

```
启动时机：lib.rs setup() 直接 spawn；POLLER_STARTED AtomicBool 防重复
循环节奏：立即扫一次 + 每 20s sleep
扫描条件（专用 SQL，弃用 ListFilter::default() 以修复 page_size=20 漏扫隐患）：
    SELECT … FROM todo_reminders WHERE is_deleted=0 AND remind_at <= now AND now - remind_at <= 24h
去重：NOTIFIED_REMINDERS: Lazy<Mutex<HashSet<i64>>>（进程内存活期）
触发：
  ① 系统通知（id = reminder.id % 2147483647）
  ② 无论成功与否 emit "todo_reminder:due"（JSON）→ 前端 sonner toast.custom
     自定义卡片（推迟 10/30/60 分钟按钮 + 关闭；P2 前为 warning toast 10s）
  ③ 记入去重集合
DB 未就绪：try_state::<AppState>() 失败时静默跳过
推迟（P2 新增，apps/desktop/src/features/todo/shared/reminder-snooze.ts）：
    删旧建新，新 remind_at = 原 remind_at + N 分钟（锚点不漂移）；
    重复续排路径防雪球守卫：任务已有其他未来提醒时只清理不克隆
移动端（P2 升级，ADR 0002 §七）：
    双通道 = α 前台轮询（同桌面 SQL，Flutter 经 FRB StreamSink）保留
    + β 系统闹钟托管（ReminderScheduler 全量重排 zonedSchedule
    alarmClock，被杀/Doze/重启可靠；通知原生构建不依赖 Dart）；
    同 id（taskId % 2^30 + 1）覆盖去重；推迟 action 走后台 isolate，
    不写 DB（FRB 不可重入），DB 收敛靠前台到期检测僵尸行静默删
```

## 七、双层密钥体系

```
【第一层：本地库加密】
主密码 ──PBKDF2-HMAC-SHA256(salt16, 600k)──► derived_key(32B)
           └─ 包裹随机 DB_Key(32B) ──► master_auth.json { encrypted_db_key, verify_hash=SHA256(derived_key), v2 }

【第二层：云同步 E2E】
同步密码 ──PBKDF2-HMAC-SHA256(salt16, 600k)──► master_key(32B)
data_key(32B 随机) ──AES-256-GCM(master_key, nonce12)──► encrypted_data_key
持久化 sync_crypto_meta.json（全 Base64）：{ salt, encrypted_data_key, data_key_nonce, iterations }
```

规则（全部平移自 wait-home，不得简化）：
- LEGACY_ITERATIONS=200k 旧包解锁成功后自动升级 600k，单调不降级。
- meta 文件损坏 → 隔离为 `*.corrupt-{ts}` 并报错，**绝不返回 Ok(None)**（防止重新 init 导致云端数据永久不可解密）。
- `change_sync_password` 只换包装不换 Data Key；`rotate_key` 换 Data Key 需配合云端全量重传。
- 跨设备 Key 分发：上传/下载 `{base_path}/orbit/crypto/config`（明文 SyncCryptoMeta JSON，无扩展名）；导入带 Fix-10 守卫（本地 meta 不一致且未 force → LocalMetaExists）。
- 同步密码缓存于系统钥匙串 service=`orbit.sync-crypto`。

## 八、云同步管线（cloud_sync）

### 本地状态与配置文件（最小字段契约，防实现漂移；精确结构以平移源码为准）

```jsonc
// sync_state.json —— 远端指纹账本（明文 JSON，性质等同缓存，可随时重建）
{
  "modules": {
    "todo": { "remote_fingerprint": "<sha256 hex | null>" }   // null = 未同步过 / 云端被清空 → 触发全量重推
  }
}
// 写盘时机：push/pull 成功后批量落盘（对应下文 Push 第 4 步）；只存指纹元数据，不含业务行数据
// 文件丢失或损坏：直接删除重建即可，代价仅一次全量重推

// sync_config.json —— 同步连接配置（整文件 AES-GCM 加密落盘；内含凭据，禁入日志/git）
{
  "engine": "webdav" | "s3",
  "webdav": { "base_url": "", "username": "", "password": "", "base_path": "" },
  "s3":     { "endpoint": "", "region": "", "bucket": "", "access_key_id": "", "secret_access_key": "", "base_path": "" },
  "interval_minutes": 60,      // 定时同步间隔；0 = 关闭定时（60s tick 判据之一）
  "auto_sync_enabled": true    // 总开关；移动端「同步开关」即此字段
}
// 双写一致性：与 DB sync_configs 表保持一致（见下文引擎与调度）；解密失败视为未配置并引导重填，不静默清空
```

### 云端路径布局（base_path 下）
```
orbit/
├─ crypto/config                    # SyncCryptoMeta
├─ _meta.orsync                     # 全局索引 GlobalMeta
└─ modules/todo/
   ├─ data.orsync                   # 模块数据
   └─ meta.orsync                   # 模块指纹 + 墓碑
```

### 载荷加密格式（区别于备份包格式！）
```
[magic(4)="OSZS"][version(1)=0x01][nonce(12)][ciphertext‖tag]
加密前先 zstd level-3 压缩
指纹 fingerprint = canonical JSON 的 sha256
```

### Push（模块间串行，规避 WebDAV 并发 MKCOL 503）
1. `state_store.load()`（sync_state.json 各模块 remote_fingerprint 账本）+ 校验 Data Key 已解锁（否则 CryptoLocked）
2. 远端校正 `reconcile_state_with_remote_meta`：远端 `_meta` 404 → 清空全部 remote_fp 触发全量重推；单模块 fp 不一致 → 清该模块 fp（应对云端被外部清空）
3. 逐模块：`SELECT * WHERE is_deleted=0`（逐条附 `_table` 字段路由标记）→ 算指纹 → 与账本相同跳过 → 变化则连同墓碑集序列化 → 加密 → 上传 data/meta
4. 上传全局 `_meta` → 批量落盘 state → 进度经 emit("sync_progress") 推送

### Pull（buffer_unordered(8) 并行）
下载解密 `_meta`（404 → empty，首启放行）→ 逐模块比对 fp → 相同跳过 / RemoteEmpty 记录 / 有变化下载解密 → `merge_items` 合并 → 更新 fp；单模块失败错误隔离进 PullResult.errors。

### 冲突合并（LWW，纯函数保证两端收敛）
- 远端有本地无（按 uuid）→ INSERT，**50 条/批单事务**（规避 SQLITE_MAX_VARIABLE_NUMBER=999）
- 两端都有 → `updated_at` 大者胜；同毫秒平局 `version` 大者胜
- 删除 vs 编辑冲突：墓碑时间戳裁决，口径 `(uuid, COALESCE(NULLIF(deleted_at,0), updated_at))`
- 本地 uuid 映射**包含软删行**（Fix-01，防一活一墓碑的僵尸行复活）+ uuid UNIQUE 索引根绝重复插入
- KeyMismatch 探针：pull 正常返回前用 global_meta 试解密，不匹配立即引导恢复页；自动补传 crypto bundle 由真值表裁决（云端有数据 + 本地 Key 存在 → Block）

### 引擎与调度
`SyncEngine`（tokio Mutex 互斥，忙时返回 skipped）：`sync_now`（备份→pull→push）/ `push_only` / `pull_then_push`。配置双存储：sync_config.json（加密）+ DB `sync_configs` 表保持一致。定时调度器 60s tick：`interval>0 && 已解锁 && 距上次≥interval` 才触发。

## 九、全量备份包 .orsync 格式

52 字节头 + AES-256-GCM 密文（magic 由 wait-home 的 `WSYN` 改为 **`ORSN`**，其余不变）：

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 4 | magic BE u32 `"ORSN"` |
| 4 | 2 | version BE u16 = 1 |
| 6 | 1 | mode：0x01 Full / 0x02 Incremental / 0x03 Snapshot |
| 7 | 1 | flags：bit0 has_assets |
| 8 | 8 | created_at_ms BE i64 |
| 16 | 12 | nonce |
| 28 | 16 | gcm_tag（镜像冗余，实际 tag 在密文尾） |
| 44 | 8 | payload_len BE i64 |

载荷 = ZIP（manifest.json + data/<table>.jsonl + crypto/bundle_meta.json）整体 AES-GCM 加密。消费端先校验 payload_len 与实际密文长度一致性（提前排除截断损坏），解压后 JSONL 逐行解析、损坏行 warn 跳过。
