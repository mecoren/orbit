## 一、总体结论

1. **协议实现核心合规**：SigV4 canonical request 构造经逐项核对符合 AWS 规范（canonical headers/signed headers/query 编码均正确）；WebDAV PROPFIND/MKCOL/DELETE 语义与坚果云 quirk 处理完整；quick-xml 结构化解析对 namespace 前缀稳健。前次 P0 十项修复全部在位（§五验证矩阵）。
2. **本次探查发现的最大缺陷是「三套附件云端命名约定互相矛盾」**——生产路径 BasePathAdapter 用裸 hash，内层适配器用 `.waitsync` 后缀，适配器里的迁移兼容代码在生产路径上实际是死代码；存量含 `.waitsync` 对象的桶会进入「每轮重复下载→哈希校验失败→丢弃」死循环。
3. **安全机制基本合格但有明确缺口**：AES-256-GCM 随机 nonce（CSPRNG）正确、PBKDF2 600k 达标、凭据不进错误链路（验证过）；缺口是 AAD 未绑定文件上下文（密文挪移防线依赖内容寻址自校验）、引擎内 sync_password 明文常驻（无 zeroize）、v2 确定性派生的盐生成仅 1 次 PBKDF2 迭代（弱密码离线暴力成本显著低于 v1）。
4. **可靠性正确的部分**：LWW+version 平局裁决确定性收敛（设计正确）、merge 单表单事务、try_lock 防重入、附件原子落盘+sha256 校验、write_atomic 文件协议。
5. **可靠性缺口集中在「中断一致性」与「可观测性」**：push 模块间无事务、`?` 中断丢后续已传模块的 state 应用；引擎全部 `log::info!` 在桌面端无处输出（tauri-plugin-log 声明了依赖但从未注册——一行接线缺失导致全部诊断日志丢弃）；conflict_count 恒 0。

## 四、探查结论复核修正（agent 报告 → 人工核源码）

1. **引擎 agent P0-4「移动端凭据必然明文落盘」——证伪**。该判断基于 Tauri 的 `#[cfg(not(desktop))]` 分支，但本项目移动端是独立 Flutter 应用（ADR 0003），orbit-desktop 不编译移动目标，该分支为死代码。实际移动端凭据存 `sync_configs` 表（SQLCipher 加密库，主密码保护，`orbit-flutter/api/sync.rs:332-395`），不经过 config_enc 的明文降级。桌面端 CEK 走钥匙串正常。**引擎内 sync_password 明文常驻问题保留为 S26。**
2. **适配器 agent P0-1 的故障链推演——修正后确认**。原推演「裸 hash 永不命中」不成立（BasePathAdapter 全链同用裸 hash 时自洽：上传裸→list 剥后缀后同名→diff 命中）；真实故障是**混合命名**场景：桶中存在任何 `.waitsync` 对象时，BasePathAdapter::list **不剥后缀**返回 `abc.waitsync` → 差集误判 → download 恰好命中 `.waitsync` 对象 → 解密成功但 **sha256 校验必失败** → 死循环。两条路径（BasePathAdapter 裸 hash / 内层 `.waitsync`）并存使同一附件可能存在两份云端对象。修复方向不变：统一口径。
