## 八、问题与建议

1. **模拟器不能经 `adb reverse` 访问宿主 HTTP 服务**：`adb reverse tcp:18080 tcp:18080` 建立成功，但设备内 `nc 127.0.0.1 18080` 收到 0 字节；改用宿主 LAN IP `http://192.168.31.110:18080` 后两台设备均正常（`nc` 得 671 B / 403，宿主 `PROPFIND` 带 Basic 得 207）。建议 WebDAV 联调文档直接写「用 LAN IP，不要用 reverse 隧道」。
2. **Windows 排除端口段会吞掉常用端口**：8123 落在系统排除段 8025–8124 内，`WsgiDAV` 起服务报 `[WinError 10013] 以一种访问权限不允许的方式做了一个访问套接字的尝试`。本轮改用 18080。建议测试服务脚本默认从高位端口起并支持环境变量覆盖（`ORBIT_DAV_PORT`）。
3. **系统代理会劫持回环请求**：本机常驻 `HTTP_PROXY`/`HTTPS_PROXY`（`127.0.0.1:10063`），未清空时服务端与 harness 的请求会被代理转成 502。服务进程、harness、Python 探针都必须显式清空 6 个代理变量别名（`HTTP_PROXY`/`HTTPS_PROXY`/`http_proxy`/`https_proxy`/`ALL_PROXY`/`all_proxy` + `NO_PROXY=*`）。
4. **`adb shell run-as cat` 会损坏二进制库**：抓 `orbit.db` 必须用 `adb exec-out run-as … cat`（不经 shell 的 CRLF 转换），否则得到 `database disk image is malformed`。建议把这条写进移动端取证手册。
5. **幂等同步仍有 48–50 s 固定开销**：移动2 零流量二次同步 48,223 ms、桌面 50,520 ms，而传输量为 0。耗时集中在服务端 523 个桶 + 258 附件（含 6 个分片文件）的 PROPFIND 列举与指纹校验。WsgiDAV 是单进程 Python 服务，**该耗时不应读成引擎基线**；但也说明大库场景下「列举成本」已超过「传输成本」，建议评估按 manifest 单文件短路。
6. **WebDAV 全量 pull 慢于 push**（移动2 110,492 ms vs 移动1 90,557 ms）：与 S3 轮相反。差异来自分片附件的多次 PROPFIND/GET 与单进程服务端串行处理。建议在报告口径里把「附件字节 / 分片数 / 对象数」与耗时并列，便于跨协议对比。
7. **验收字段 `downloaded_chunks` 不存在**（同 S3）：`SyncState` 无该字段，零流量口径用「epoch 不变 + 桶指纹不变 + `pulled_modules`/`downloaded_attachments` 计数 + 前后账本比对」替代。
8. **`version` 元数据跨端不一致**（S3 轮发现，本轮未触发）：建议引擎在 pull 合并时传播远端 `version`，或在验收规范里显式剔除该字段。
9. **移动端同步密码不缓存**：重启即回「已锁定」，自动化必须先解锁；且解锁后页面停在「云同步配置」子页（**没有「立即同步」按钮**），必须先点左上「返回」退回设置页。本轮已把「解锁 → 回设置页 → 点立即同步」固化进 `sync_mobile2.py`。
10. **移动2 序列号漂移**：需求写 `127.0.0.1:16416`，本轮该端口恒 offline，改用同机第二模拟器在线序列号 `127.0.0.1:5557`（型号 SM-S9110、版本 0.1.0+6 与需求一致）。建议需求侧改为「按在线序列号取第二台模拟器」。
