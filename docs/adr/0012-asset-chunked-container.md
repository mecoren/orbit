# ADR 0012：附件云端容器 `OSAC`（分块 AES-GCM）

- **状态**：已采纳（2026-10-23）
- **相关**：`docs/13 §6.2 M3`、`docs/07 #94`、ADR 0011（备份 v2 帧式容器）
- **实现**：`crates/orbit-core/src/cloud_sync/asset_container.rs`

## 背景

附件同步此前沿用模块数据的整包载荷（magic `OSZS`）：zstd 压缩整份明文后单次
AES-256-GCM。加密/解密必须同时持有整份明文与整份密文，50MB 附件在推送上行
与拉回时都会稳定多出上百 MB 峰值；再叠加 4 路并发，峰值随附件数量放大。

本地写入/预览也有同类问题：`add_task_attachment(&[u8])` 要求调用方先整文件
读入（桌面前端还先读成 JS 数组），`read_task_attachment` 返回 `Vec<u8>` 让整份
内容进渲染进程。附件是最后一个「真实可打爆内存面」。

## 决策

新附件对象一律使用 **`OSAC` 分块容器**，任何时刻内存只有一帧明文 + 一帧密文
（4MiB 级），峰值与附件大小解耦。存量 `OSZS` 对象读兼容，不强制迁移。

### 文件布局

```text
[magic "OSAC" 4B][version u8][chunk_plain BE u32][total_plain BE u64]
[chunk_count BE u32][nonce_base 12B]
重复 chunk_count 次：
  [seq BE u64 8B][ct_len BE u32 4B][ciphertext+tag]
```

头部不加密：只含解密所需公开参数（帧大小/明文长度/nonce 基值），不含业务
内容。帧数与明文长度一起进头部，读侧**先校验再分配**，防伪造超大长度打爆内存。

### nonce 派生与确定性

```text
nonce_base = SHA256(data_key ‖ object_id ‖ "orbit-asset-container-v1")[0..12]
frame_nonce = nonce_base 后 8 字节 XOR seq
AAD = magic ‖ version ‖ seq ‖ total_plain
```

`object_id` 取附件明文 sha256（即云端对象键）。因此**同 key + 同内容 ⇒ 同容器
字节**：重试、多设备重加密、断点续传都不会产生不同密文，内容寻址的幂等性
得以保留。帧序号进 AAD，删帧/换序/跨对象拼接都会让 GCM tag 失败；截断由
「帧数 × 总长」与末尾整体 `sha256(明文) == object_id` 双重兜住。

### 为什么不做整包压缩

新容器不对帧做 zstd：附件以图片/PDF/压缩包为主，压缩收益低，而每帧再挂一个
解压缓冲会把「一帧驻留」的承诺变成两份。需要压缩的场景（备份 JSON）已由
ADR 0011 的 v2 容器承担。

## 兼容与升级

- **读**：按首 4 字节分流——`OSAC` 走本容器流式解密；其余走 `decrypt_payload`
  （旧 `OSZS` 整包路径），旧附件照常可打开/下载。
- **写**：新挂载附件一律 `OSAC`；单对象路径不变（`assets/{hash}.orsync`），
  WebDAV 分片协议与 S3 multipart 的对象布局不变。
- **旧客户端**：读到 `OSAC` 会报「payload 格式不匹配」/版本不匹配。这是**预期
  失败而非静默损坏**，发布说明需标注「附件同步格式升级，旧版本需升级后再同步」。
- **回滚**：已上传的 `OSAC` 对象无法被旧版本读取；回滚需先在旧版本上重传附件，
  或接受旧版本无法拉取新附件。开发期可删除云端附件对象让对端重传（不涉及
  数据丢失：附件明文在源设备仍在）。

## 备选方案

1. **保持整包 `OSZS`，只把分片上传做流式**：加密本身仍要整份明文+密文，峰值
   不降，否决。
2. **每帧独立对象（多对象上传）**：对象键契约变化、清单维护与 GC 复杂度陡增，
   且适配器分片协议已承担「分段传输」，否决。
3. **本地附件也加密落盘**：需要常驻本地密钥（无同步密码的用户没有 Data Key），
   会把「本地优先、离线可用」与密钥生命周期绑死，超出本项范围；本地库仍由
   SQLCipher 保护元数据，附件明文落在应用数据目录（与现状一致），另行立项再议。

## 影响

- 附件推送/拉回峰值：50MB 口径由 ~50MB 降到 8–12MB（`perf-metrics` 实测）。
- 云端对象体积略增（去除 zstd + 每帧 12B 头 + 每帧 16B tag），对同步流量影响可忽略。
- 新增一档格式版本，后续变更必须递增 `VERSION` 并保留旧版本读路径。
