## 五、Orbit 独有优势（TickTick 无对应）

1. **双层端到端加密**：SQLCipher 本地库（PBKDF2-HMAC-SHA256 600k 单调不降级）+ 云端仅存 AES-256-GCM 密文（zstd 压缩、密钥不出本机）——TickTick 为云端明文/服务端加密，账号即边界。
2. **本地优先 / 零遥测 / 免注册免订阅**：无账号体系、`PRIVACY.md` 隐私披露。
3. **自托管云同步三协议**：WebDAV / S3 / 阿里云 OSS，数据可落在自己的服务器；表级分桶差量 + 单一清单 CAS + HLC 逻辑时钟裁决 + 冲突败方副本可恢复 UI。
4. **全量备份**：`.orfullsync`（AES-256-GCM）本地 + 云端副本，恢复预览 + 危险分级 + 两段式确认 + 5s 时停。
5. **数据主权闭环**：明文导出 JSON（8 表）/CSV（UTF-8 BOM）/ICS（VTODO）+ CSV 三档导入（orbit/Todoist/**TickTick**）+ ICS 导入——TickTick 用户可零成本迁入。
6. **任务关联 6 类关系**（个人待办品类少见）+ 通知历史中心 + 数据库维护一键化（WAL checkpoint/VACUUM/附件 GC）。
7. **工程代差**：Rust 核心 100% 下沉 + Tauri 2，冷启动 ~320ms / 空闲内存 ~42MB（Electron 系一个数量级优势，docs/07 §4.2）；CI 四 job + 内存门禁三件套 + 同步故障注入测试矩阵。

## 六、结论

1. **总体判断**（2026-09-30 更新）：§3.1 三项建议（G1 周视图 / G2 持续提醒 / G3 每日摘要）与 §3.2 的
   清单文件夹分组（M8）**均已落地**——日历模块不再有档位缺口，清单侧补齐层级分组。剔除定位主动取舍的
   排除项（番茄/习惯/协作/AI/集成）后，Orbit 对 TickTick 的剩余真实差距收敛为**一个模块 + 一个小颗粒**：
   任务时长/时间块（M9，与时间轴互为表里，也是多日/多周档的前置）为主，倒数日（M13）为小颗粒。
2. **批次复盘**：原建议批次「G1 → G2 → G3」实际按 **G2 → G3 → G1** 执行（先做改动面小的 core 侧能力，
   把跨端 UI 面最大的周视图收尾），随后接 §3.2 的 M8；四项均零回归落地。M13 视需求热度排队；M12 维持不启动。
3. **反向叙事**：Orbit 不应也不需要在功能面上追平 TickTick 的生产力套件边界；护城河在「加密 + 数据主权 + 自托管同步 + 性能」四件套（§五），这是 TickTick 商业模式（云账号 + 订阅）结构上无法跟进的。
4. 平台覆盖（iOS/iPad/Watch/Web）是 TickTick 的长期优势项，Orbit 按 docs/06 节奏推进 iOS 验收即可，不建议为对齐而扩张平台面。
