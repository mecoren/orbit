# 17 同步端到端测试手册（S3 / WebDAV × 桌面 / 移动）

> 面向「换机恢复、跨端一致、冲突收敛」的手工验收手册。
> 配套工具：`crates/orbit-core/examples/seed_demo_db.rs`（`--projects/--history/--labels/--attachments` 档）。
> 本手册不替代自动化用例：协议级回归仍以 `cargo test -p orbit-core --test sync_fault_matrix` 等为准。

## 一、先读：5 条会直接导致假红的事实

| # | 事实 | 后果 / 正确做法 |
|---|---|---|
| 1 | 云同步连接配置存在 **业务库 `sync_configs` 表**（双端唯一事实源），桌面另有 `sync_config.enc` 镜像 | 删 `orbit.db` 必然删掉激活配置。「清空数据但保留云配置」在本项目**不成立**，只能「清库前记录 → 清库后重建 → 校验一致」 |
| 2 | `sync_state.json` 里的 `manifest_epoch` 与云端相同时，pull 会**整轮跳过**（`pull.rs` 的 epoch 快速跳过） | 清库必须同删 `sync_state.json`，否则空库「立即同步」拉回 0 条 |
| 3 | WAL 模式下还有 `orbit.db-wal` / `orbit.db-shm` | 不删会把旧数据带回新库；必须三个一起删 |
| 4 | 产品只有**「立即同步」**（pull + push 一次完成） | 没有「同步到云端 / 同步云端」两个按钮；拆单向只在排障页 |
| 5 | 移动端**没有定时同步调度器**，只有「修改后立即同步」（5s 防抖 `push_only`） | 移动端不要等定时同步；自动同步用例只验 5s 防抖这一条 |

另外两条纪律：

- **禁止**调用 `cloud_sync_rekey`：它不做 pull 合并，会用本机数据覆盖云端。
- **禁止**删除 `sync_crypto_meta.json`：它是同步密码 / Data Key 元数据，删了就回到「未设置密码」。
- 测试数据必须使用独立 `base_path`（如 `orbit-sync-test/{runId}/s3`），不得与既有数据共用。

## 二、测试矩阵

同一套数据在 4 个组合上跑，S3 与 WebDAV 各一轮：

| 编号 | 组合 | 覆盖 | 优先级 |
|---|---|---|---|
| M1 | 移动1 → 移动2 | 协议正确性、首次全量、二次增量幂等 | 必测 |
| M2 | 移动1 ↔ 移动2（并发） | LWW 裁决、`sync_conflicts` 败方留档、墓碑竞态 | 必测 |
| M3 | 移动1 → 桌面 | 壳层差异：DB 路径、DTO 镜像、附件分片、时区 | 必测 |
| M4 | 桌面 → 移动2 | 反向同上 | 必测 |
| D1 | 桌面 ↔ 桌面 | 与 M1/M2 在 core 层等价，差异仅 sidecar / keyring | 抽检，可省 |

> 只测「桌面 → 移动」不够：单向全量只验证冷启动恢复，验证不了增量、并发冲突与墓碑传播。

## 三、环境与数据目录

| 端 | 启动 | 包名 / identifier | 数据目录 |
|---|---|---|---|
| 移动1 | `flutter run -d 127.0.0.1:16384 --flavor dev` | `cn.wait.orbit` | `/data/data/cn.wait.orbit/files/` |
| 移动2 | `flutter run -d 127.0.0.1:16416 --flavor dev` | `cn.wait.orbit` | 同上（不同设备，天然隔离） |
| 桌面 | `pnpm dev`（debug） | `cn.wait.orbit.dev` | Windows `%APPDATA%\cn.wait.orbit.dev\`；macOS `~/Library/Application Support/cn.wait.orbit.dev/` |
| 桌面（release） | 安装包 | `cn.wait.orbit` | 同上换 identifier |

目录内关键文件：

```text
orbit.db              业务库（含 sync_configs）
orbit.db-wal/-shm     WAL 日志（清库必删）
sync_state.json       同步账本（epoch / 桶指纹 / 水位线；清库必删）
sync_crypto_meta.json 同步密钥元数据（保留！）
sync_config.enc       桌面端配置镜像（保留；移动端无此文件）
attachments/          附件明文缓存（{sha256} 文件名）
backups/              全量备份包
```

同名文件在移动端位于 `getApplicationSupportDirectory()`，Android 即 `files/`。

## 四、阶段 0：配置快照（每轮开始 + 清库前各做一次）

逐项抄录并截图，落到 `sync-config-snapshot-{runId}.json`：

- 协议（s3 / webdav）
- endpoint、bucket、region
- access key / 用户名（凭据不回显，需从测试记录取）
- secret key / 密码
- 远端路径 `base_path`
- 请求超时、跳过 TLS、自动同步开关与间隔、修改后立即同步
- 同步密码卡：`hasPassword` / `isUnlocked`

桌面端可直接读：

```bash
# 只返回非敏感字段（凭据不回显）
# 前端：设置 → 同步与备份；或 IPC 调 sync_config_get
```

「测试连接」必须通过并记录返回。

## 五、阶段 1：清库（每轮同步前，对两台移动 + 桌面各做一次）

### 5.1 移动端

```bash
SERIAL=<127.0.0.1:16384 | 127.0.0.1:16416>
adb -s $SERIAL shell am force-stop cn.wait.orbit
adb -s $SERIAL shell run-as cn.wait.orbit rm -f \
  files/orbit.db files/orbit.db-wal files/orbit.db-shm files/sync_state.json
# 可选：清附件缓存（验「空缓存重新拉附件」）
adb -s $SERIAL shell run-as cn.wait.orbit rm -rf files/attachments
# 保留：files/sync_crypto_meta.json
adb -s $SERIAL shell run-as cn.wait.orbit ls -l files/
```

### 5.2 桌面端

退出应用后：

```powershell
$dir = "$env:APPDATA\cn.wait.orbit.dev"
Remove-Item "$dir\orbit.db","$dir\orbit.db-wal","$dir\orbit.db-shm","$dir\sync_state.json" -ErrorAction SilentlyContinue
# 保留：sync_config.enc、sync_crypto_meta.json
```

### 5.3 重建配置并校验

重启应用 → 设置 → 同步与备份 → 按阶段 0 快照原样重填 → 测试连接 → 保存。
逐字段比对 `sync_config_get` 与快照；同步密码卡应显示「已设置」，输入密码解锁成功。

> 若忘记记录凭据，只能从 `sync_config.enc` 反解（桌面，需要 CEK）或重新申请 AK/SK。
> 移动端无配置镜像，凭据丢失只能重填。

## 六、阶段 2：造数据（只在移动1）

### 6.1 生成

```bash
cargo run --release -p orbit-core --example seed_demo_db -- \
  --out target/seed/orbit.db --profile sync-e2e --rows 40000 --projects 8 \
  --history 1999:2018 --labels 40 \
  --attachments 300 --big-attachments 2
```

`--profile sync-e2e` 是同步压测档；不带该参数（默认 `demo`）仍是旧的轻量首屏画像。
`--relations` / `--saved-filters` / `--templates` 可覆盖派生表数量。

产出画像（2026-11-10 实测，11 张可同步表合计 214,109 行）：

| 数据 | 实测 / 目标 | 说明 |
|---|---|---|
| 项目 | 9（8 新增 + 内置收件箱） | 1 个历史项目（1999–2018），6 个近期，1 个归档；前 6 个保留父子清单 |
| 主任务 | 40,000 / 40,000 | 历史项目约 1/7（归档项目不承接任务）；近期项目每 3 条有 1 条落在 2019 至今 |
| 子任务 | 58,628 / 约 60,000 | 每任务 0–3 个，压测档按 splitmix 散列 |
| 标签 / 关联 | 40 / 78,287（目标约 80,000） | 每任务 0–4 个，跨项目复用、单任务多标签 |
| 评论 | 19,201 / 约 20,000 | 长文本 / 换行 / emoji / Markdown |
| 提醒 | 14,601 / 约 15,000 | 未来 1–3 天，含持续提醒；重复规则在任务侧全覆盖 |
| 任务关系 | 3,000 / 3,000 | `blocks` / `relates_to` 各半 |
| 保存的筛选器 / 模板 | 20 / 20 | 条件 JSON、模板 payload JSON |
| 附件 | 300 账本 + 303 关联 | 前 `--big-attachments` 个为 8.5MiB（触发 WebDAV 分片 `assets_parts/{hash}/`） |
| 软删 | 799（2%） | 墓碑，验 `tombstones/{table}/{YYYY-MM}` 传播 |

> 派生表比目标略少约 2%，因为 2% 的软删任务按业务语义不再挂子任务/标签/评论/提醒。
> 需求写的「总目标约 15 万行」与逐表目标（合计约 21.8 万行）本身不一致，
> 本手册以**逐表目标**为准。

字段覆盖：优先级 0–3、状态 pending/doing/done、无日期/逾期/今天/近 7 天/未来、
`start_date`、时长、收藏、我的一天、Markdown 描述、重复规则（日/周/月/年、工作日掩码、
每 2 周、每月第 N 个星期 X、按日期结束、按次数结束）。

### 6.2 推到真机

```bash
SERIAL=127.0.0.1:16384
adb -s $SERIAL shell am force-stop cn.wait.orbit
adb -s $SERIAL push target/seed/orbit.db /data/local/tmp/orbit.db
adb -s $SERIAL shell run-as cn.wait.orbit cp /data/local/tmp/orbit.db files/orbit.db
adb -s $SERIAL shell run-as cn.wait.orbit rm -f files/orbit.db-wal files/orbit.db-shm
# 有附件时目录一起推（先清目标，否则 cp -r 会套成 attachments/attachments）
adb -s $SERIAL shell rm -rf /data/local/tmp/attachments
adb -s $SERIAL push target/seed/attachments /data/local/tmp/attachments
adb -s $SERIAL shell run-as cn.wait.orbit rm -rf files/attachments
adb -s $SERIAL shell run-as cn.wait.orbit cp -r /data/local/tmp/attachments files/attachments
adb -s $SERIAL shell am start -n cn.wait.orbit/.MainActivity
```

校验：

```bash
adb -s $SERIAL shell run-as cn.wait.orbit ls -l files/
# 期望：orbit.db 约 10–30MB（4 万任务）、attachments/ 300 个文件
```

> **加密库陷阱**：真机启用主密码时库是 SQLCipher 加密的，明文种子库不能直接替换
> （打不开）。此时改用应用内 `.orfullsync` 导入，或临时关闭主密码，测完恢复。

## 七、阶段 3：同步时序

严格按序执行，每步记录耗时与 `sync_history` 最新一条：

| 步 | 端 | 操作 | 期望 |
|---|---|---|---|
| 1 | 移动1 | 设置 → 同步与备份 → 立即同步 | push 计数 ≈ 全量行数；耗时记录 |
| 2 | 移动2 | 重填配置（同 base_path）→ 解锁 → 立即同步 | 空库 + 已删账本 → 全量 pull；行数与移动1 一致 |
| 3 | 移动2 | 再点一次立即同步 | epoch 未变 → `downloaded_chunks = 0`，接近零流量 |
| 4 | 桌面 | 填同一配置 → 立即同步 | 全量 pull（M3） |
| 5 | 桌面 | 改 1 个任务标题 + 新建 1 个项目 → 立即同步 | push 增量 |
| 6 | 移动2 | 立即同步 | 看到步 5 的变更 |
| 7 | 移动2 | 改回标题 → 立即同步 | push 增量 |
| 8 | 桌面 | 立即同步 | 变更回流（M4） |

## 八、阶段 4：一致性验证（前 3 项必过）

### 8.1 行数对账

双端执行 `plaintext_export_json`，只取 `table_counts`，11 张表逐表相等：

```text
todo_projects / todo_tasks / todo_subtasks / todo_labels / todo_task_labels /
todo_comments / todo_task_relations / todo_reminders / todo_task_attachments /
todo_saved_filters / todo_templates
```

`exclude_deleted` 传同一值；再用 `false` 跑一次对比墓碑数。

> 不要一次性 diff 全量 JSON：4 万行会顶到桥与内存上限。

### 8.2 云端视图对账（最强判据）

双端 `cloud_sync_get_state`：

- `manifest_epoch` 相等
- `remote_tables` 的「表 → 桶 → 桶指纹」完全相同
- `remote_tombstones` 相同

三项全等 ⇒ 两端看到的云端分桶视图一致。

### 8.3 行级抽样

每表按 `uuid` 排序取首/尾各 50 条 + 随机 100 条逐字段比对。比对前：

- 剔除本地自增 `id`
- 整数外键（`project_id` / `task_id` / `label_id` / `other_task_id`）换成父行 `uuid`
- `updated_at` 允许毫秒级差异，其余字段必须全等

### 8.4 附件

- `attachments/` 文件数相同、`sha256` 集合相同
- `sys_attachments` 的 `is_local_cached = 1`
- 8.5MiB 附件在两端均可打开（WebDAV 走 `assets_parts/{hash}/` 分片）
- 同 hash 被多任务引用时，云端对象只有一个

### 8.5 回收站与墓碑

- 双端回收站条数一致
- 软删记录在对端是**软删**，不是物理消失，也没有被复活
- 删除操作同步后，对端 `deleted_at` 与本端一致

### 8.6 统计

`stats_aggregate(year)` 对 1999 / 2005 / 2018 / 2026 四年结果相等（历史区间按年都有数）。

## 九、阶段 5：冲突与异常（S3 轮必做）

1. **并发改同一任务**：双端离线改同 uuid（标题不同，间隔 >1s）→ 先后立即同步。
   期望：`updated_at` 大者胜（同毫秒比 `version`）；败方整行进本端 `sync_conflicts`；
   不得出现两条同 uuid 记录。
2. **墓碑传播**：移动1 删除项目 → 立即同步 → 移动2 立即同步 → 移动2 该项目进回收站，
   重启后不复活。
3. **密码错误**：移动2 输错同步密码 → 必须报 `wrong_password`，本地数据不得被清。
4. **中途取消**：立即同步过程中点「取消同步」→ 回待命态；再点立即同步可继续成功。
5. **断网**：飞行模式下立即同步 → 明确失败提示；恢复网络后重试成功，行数不变。

## 十一、常见假红与排查

| 现象 | 先查 |
|---|---|
| 空库同步后 0 条 | `sync_state.json` 没删，epoch 相同被跳过 |
| 清库后数据又回来了 | `-wal` / `-shm` 没删 |
| 「尚未配置同步」 | `sync_configs` 被清，重新填配置 |
| 同步密码一直未解锁 | `sync_crypto_meta.json` 被删 / 密码错误 |
| 附件上传报「读取本地附件失败」 | `attachments/` 没推、`sys_attachments.local_path` 指向旧机器路径 |
| WebDAV 大附件失败 | 服务端单文件上限 / 分片目录 `assets_parts/` 权限 |
| 统计年份为空 | 历史项目任务 `done_at` 未落在历史区间（种子参数没生效） |
| 两端行数差 1 | 内置「收件箱」项目：初始化自动建，两端都应有，对比时口径要含它 |
| 「测试连接」成功但立即同步必失败 | 连接测试只走 GET/LIST，覆盖不到写路径。阿里云 OSS 曾对条件 PUT 的 `If-Match` / `If-None-Match: *` 回 `400 NotImplemented`，2026-11-10 已改为 `x-oss-forbid-overwrite` + HEAD 比对 ETag 的方言分支；别的 S3 兼容实现若同样拒条件头，先看 `sync_history.error_message` 的 `NotImplemented`，别拿连接测试当同步可用性判据 |
